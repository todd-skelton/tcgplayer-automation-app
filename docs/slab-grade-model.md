# Cross-grade evaluation foundation

Run `npm run evaluate:slab-grades` to regenerate the initial diagnostic, cohort evaluation artifact and adoption registry. The sanitized source has 105 title-compatible, single-quantity observations across four Japanese Terastal Festival cards. It reproduces the earlier **24.624450894%** mean absolute percentage error for a leave-one-card-out PSA 10-to-9 ratio diagnostic. This comparison uses delivered medians captured after the sales, not held-out future transaction validation. Four observations lack stable sale IDs and exact edition/finish/stamp metadata were not verified.

The predeclared adoption policy is in `model/gradeModelPolicy.json`; results are in `docs/slab-grade-model-evaluation.json`. There are **zero verified forward-validation events and zero enabled cohorts**. Error and interval-coverage metrics for unsupported cohorts stay null rather than claiming performance from unverified matches. The empty, versioned registry includes the source fixture's SHA-256 digest. The review page explains the absence of a cross-grade estimate; PSA 1 retains an explicit collector-grade message.

`gradeModel.ts` supplies the offline candidate as pure functions. Grading effects are fitted to per-card log ratios within exact cohort keys, with equal card contributions and shrinkage toward the robust cohort median. The held-out card contributes its own observed price level. Target-grade sales gain weight continuously as effective direct evidence grows. PSA 1, Pristine/Black Label families, unknown cohort fields and cross-grader transfers cannot borrow from the standard-grade model. There is no imposed monotonic ladder. Model parameters carry algorithm/policy versions, the fitting cutoff and source/event lineage and survive JSON serialization deterministically.

`gradeModelEvaluation.ts` compares direct, median-ratio and fitted candidates using five folds with separate training, calibration and test cards plus ordered time boundaries. Capture timestamps establish availability; sale dates alone do not. Unknown IDs/matches, contradictory duplicate events, provider estimates and multi-item averages are excluded. Hidden-grade scenarios remove the target grade from card-level history. Calibration is fitted on earlier transactions from separate cards and tested on later held-out transactions. Prediction caching within each offline fold and pregrouped history avoid rescanning the entire dataset for each outcome.

Adversarial review found and fixed a potential hidden-grade calibration leak by excluding both calibration and test cards from fitted priors. It also bounded/validated inputs, excluded contradictory duplicates, separated label families, required valid fitting/policy versions, preserved Chicago research dates, cached repeated evaluation forecasts and required whole-day evaluation boundaries for day-precision sales. Tests cover future capture/outcomes, deterministic input permutation and serialization, direct-evidence shrinkage, inverted grade relationships, sparse abstention and policy gates. The synthetic 40-card/240-test-transaction fixture takes roughly 200 ms locally; synthetic outcomes never count toward production adoption.

This is the evaluation foundation for #29, not an enabled runtime model. That issue remains open for verified dated evidence, an adopted cohort with calibrated uncertainty, compact approved parameter publication and inference/cache integration into saved recommendations. Those integrations are intentionally deferred until actual evidence supports adopting a model. Fitting is never added to an interactive request, and this change adds no runtime dependency, database table or provider read. It does not change direct valuation policy or publish prices.
