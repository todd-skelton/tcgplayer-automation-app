# Native seller review and publication (pending live validation)

This change builds on the seller OAuth adapter in draft PR #38. Inventory can explicitly import active eBay listings or read one listing's details. Both paths verify the authenticated seller. The saved preview gains a separate live review: authenticated GetUser/GetItem reads capture the exact seller, item, certificate, price, quantity and a fingerprint of the returned listing configuration. Reading a preview or publication history never contacts eBay.

Production credentials remain server-only: `EBAY_SELLER_CLIENT_ID`, `EBAY_SELLER_CLIENT_SECRET`, and `EBAY_SELLER_REFRESH_TOKEN`. Use a dedicated keyset for this personal application. The user explicitly reserved the existing Chase Sets keyset for the separate multi-user platform. eBay's **Request another keyset** flow requires support approval; developer support has been activated, and a separate “Slab Pricing” request has been drafted. No additional keyset, seller token or exemption has been created yet.

`EBAY_SLAB_PUBLISHING_ENABLED` defaults to disabled. When OAuth is configured, disabled mode allows live plan preparation and read-only reconciliation of an earlier possible write. Only setting it to the exact value `true` permits the HTTP approval action to start a new write. Keep it disabled until real account/listing reads and a separately reviewed concrete publication plan are ready. Neither maintenance nor a price preview can approve a publication.

The initial publisher supports US/USD, fixed-price listings with one available item, a matching certificate, no variations and no SKU. SKU-bearing listings remain unsupported, including otherwise valid Trading listings, until their listing origin can be independently verified. The Inventory API requires SKUs and has incompatible revision semantics; an ItemID tracking mode alone does not prove the listing was created outside that model. No inventory migration is performed.

The narrow [ReviseInventoryStatus](https://developer.ebay.com/devzone/xml/docs/reference/ebay/ReviseInventoryStatus.html) request contains only ItemID, StartPrice/currency and MessageID. It sends no quantity, title, shipping or offer settings. The transport exposes separate read and price-revision capabilities and shares one bounded token exchange per run. Inventory callers cannot invoke the price mutation through their read capability. A publisher read admits at most one dispatch; later requests need the executor's persisted intent and a new read.

Only a successful acknowledgement matching the intent correlation and item ID is accepted. All uncertain responses remain unknown. The execution ledger still requires [GetItem readback](https://developer.ebay.com/devzone/xml/docs/reference/ebay/GetItem.html) of price and protected fields before confirmation. The fingerprint retains returned listing configuration, including descriptions, item specifics, offer policies and business profiles, while excluding current-price derivatives, seller reputation and view/watch counters. Raw descriptions or seller objects are not added to the ledger.

The review UI shows the immutable seller/listing/certificate and old/new price, requires an explicit checkbox and approval action, and explains that eBay offers no atomic compare-and-update for this call. Ambiguous `writing`/`reconcile` intents remain accessible across newer previews; unresolved entries take priority within the bounded 25-row listing history. Disabling new writes still permits reconciliation. Cancellation cannot erase a possible write. A confirmed outcome can prepare a separate restore only after a fresh preview selects its prior price, followed by its own approval/readback.

## Validation and remaining work

`npm test`, `npm run typecheck`, `npm run build`, and the guarded PostgreSQL workspace integration pass. The latter exercises the actual HTTP composition and XML adapter against synthetic eBay responses: read-only preparation, explicit approval, minimal dispatch, readback, terminal retries, lost acknowledgements, new-write disablement, recovery and more than 25 newer history entries. Unit tests verify authenticated account/capability gates, protected-field changes, returned-object isolation and correlation mismatches. No real eBay price write is part of these tests.

The implementation remains in draft until the dedicated keyset is approved/activated, seller OAuth is completed, native inventory/detail shapes and listing origin are verified, and a separately approved real before/after plan passes. Parser/policy adjustments found by that proof require another adversarial review. Model adoption, native order outcomes and unattended publication remain separate unfinished issues.

Local browser validation confirmed that a synthetic USD 100 → USD 125 saved preview exposes the new publication-history section while seller import, details and live preparation remain unavailable without OAuth. No real provider request was made, and the synthetic identity, listing, evidence, recommendation and preview were removed afterward. Static build checks still show no slab implementation on unrelated pricing routes, unchanged existing TCGplayer worker sizes and route growth below the existing 4 KiB gate.
