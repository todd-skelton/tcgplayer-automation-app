# Slab inventory core

Migration `026_add_slab_inventory.sql` stores seller accounts and listing/variation rows. Rows use seller + eBay item ID + variation key, never SKU or certificate, as their unique inventory identity. A bounded batch reconciliation preserves manual identity assignments and notes. Separate physical slabs can share a valuation group while remaining separate stock. Listing revisions advance when price, quantity, state, metadata or identity changes; publication must check them alongside the confirmed identity revision.

`/api/slab-inventory` GET accepts `seller` and an optional `after` cursor, returning up to 100 records and the account revision. Same-origin JSON POST supports `import-csv` (CSV text), `import-manual` (listing snapshots), `resolve-identity` (row ID/revision) and `assign-identity` (row ID/revision, confirmed identity ID and note). Import requires the account revision read before the import began. Bodies are limited to 3 MiB, CSV to 2 MiB and batches to 5,000 rows. The feature reuses the existing CSV parser and shared bounded JSON reader; no dependency is added.

Required CSV columns are `item_id,title,price,currency,quantity,state,format`. State is `active`, `ended` or `sold`; format is `fixed-price`, `auction` or `unknown`. Optional columns: `variation_key,sku,grader,certificate_number,shipping_amount,shipping_currency,shipping_policy_id,card_name,set,card_number,year,language,finish,edition,stamp,game,grade_label,grade_number`. IDs and certificates remain strings, preserving leading zeros. Blank shipping is unknown. CSV/manual imports are always partial and cannot retire unseen listings.

The repository also supports complete active-inventory snapshots from a future verified seller adapter. Only complete snapshots can mark unseen active rows `missing`; absence does not assert why a listing ended. Row locking/account revisions reject concurrent or older imports. A summary refresh retains earlier certificate/specifics while leaving an explicit detail-review flag. Lots, multiple quantities, unsupported formats and reused certificates remain visible with review reasons.

**Automatic seller import remains in draft PR #38 / issue #24.** Chrome shows the existing Chase Sets production keyset disabled pending account-deletion notification configuration, which also disables token creation. The exemption form requires declaring no eBay data is persisted; no exemption was submitted or credential rotated. A suitable endpoint/hosting destination is needed before completing seller OAuth and proving a Trading API read includes manually created Pokebash listings. The unproven seller adapter and its XML dependency are not included in this core slice. Market evidence and CSV/manual review can proceed independently.

Isolated PostgreSQL tests cover idempotence, complete/partial updates, sold/missing stock, duplicate SKU/certificate, separate Zapdos listings with one valuation group, manual corrections, summary detail retention, revision races, account isolation, pagination and API origin/revision guards. A local 5,000-row import measured 663–770 ms; a 200-row page 9–12 ms. These are development measurements.
